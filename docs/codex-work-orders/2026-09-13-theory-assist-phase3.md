## いちばん大事な制約

### 公開中のダビ娘の見た目を、1ピクセルも変えないこと

ダビ娘は `https://love-dabimas.github.io/dabimas-data/dist/` で公開中で、
**ダビふぁくとは関係なく使っている利用者がいる。** 今回カードから消す
非凡・天性・因子カウント表は、その人たちが見に来ている情報そのものである。

したがって**変更はすべて埋め込みのときだけ効かせる。** 仕掛けは既にある。

```ts
// src/features/embed/model/embedMode.ts
const isInFrame = window.parent !== window;
export const EMBED_MODE = !isInFrame ? "none" : ... ;
export const IS_EMBEDDED = EMBED_MODE !== "none";   // embed または picker
export const IS_PICKER  = EMBED_MODE === "picker";  // 馬選択のときだけ
```

`IS_EMBEDDED` は **iframe の中にいることとクエリの両方**を見ている。単体の URL を
直接開けば `?embed=1` を付けても `"none"` になる。URL だけでは埋め込みにならない。

- **TSX での出し分け** … `IS_EMBEDDED` / `IS_PICKER` で分岐する。
  `src/features/search/ui/HorseResultCard.tsx` に既に前例がある（❤ と選択）。
- **CSS での出し分け** … `<html>` に付く `.embed-mode`（馬選択は `.embed-mode--picker` も）
  で囲う。**`src/styles/embed.css` に書くこと。**
  `src/styles/app.css` や `legacy.css` の既存ルールを書き換えない。

既存の設計書（`C:/derby/dabimasFactor_new/docs/dabimusume-integration-design.md` §12 の 15）
にも「クエリなしで開くと、今のダビ娘と同じ見た目である」という受け入れ基準がある。
これを引き続き満たすこと。

### 11月まで公開しない

統合版の本番稼働は2026年11月である。

**`main` にマージしないこと。push もしないこと。** このリポジトリは毎週金曜18時の
GitHub Actions（`.github/workflows/update-horse-data.yml`）が `main` をビルドして
`dist/` をコミット・push する。`main` に入れた時点で、次の実行で本番に出る。

`dist/` を手で編集・コミットしないこと。ビルド成果物はワークフローが作る。

## 背景と目的

ダビふぁくに「配合理論補助」という画面を作っている。繁殖牝馬を起点に、代ごとに
種牡馬を選び、3代先までの配合理論を確認するものである。その種牡馬選びに
ダビ娘を使う。

ダビ娘のカードは実在馬の実測データ（非凡・天性・能力値）を前提に組まれているが、
配合を考える場面で要るのは血統まわりだけである。さらに、あとの Phase で
ダビふぁくの自家製馬（実際に走っていない仮想の産駒。能力値が存在しない）を
候補に混ぜる。そのため**埋め込みのときはカードの項目を絞る。**

この指示書は**カードの見た目だけ**を扱う。自家製馬の受け取りと配合理論での
絞り込みは Phase 4 で、別の指示書になる。

## 作るもの

`picker-card-mock.html` が正である。配置・大きさ・文言はこれに合わせること。
モックは素の HTML/CSS/JS だが、コードを写すのではなく React + TypeScript で組み直す。

### 1. カードの項目を絞る（`IS_EMBEDDED` のとき）

残すもの。

| 項目 | 備考 |
|---|---|
| レア | 既存のバッジのまま |
| 馬名（因子付き） | 既存のまま |
| 脚質・成長・実績・気性・安定・底力・健康・適正力・距離 | 9項目。既存のまま |
| 血統表 | 15行。既存のまま（開閉は下の 3） |

**消すもの。** 非凡、天性、全因子カウント表、1薄め・2薄め表、配合理論マーク
（`renderTheoryMarks` が出している 完璧／超完璧／奇跡／至高 の ○ − 表示）。

配合理論マークを消す理由: あれは**その馬が単体で持っている素質**で、相手に関係なく
決まる値である。Phase 4 で出す「いまの繁殖牝馬と組んだときに成立する理論」とは
別物なので、並べると混乱する。

### 2. 面白・見事の系統をカード右上に出す（`IS_EMBEDDED` のとき）

2行。上が面白（オレンジ）、下が見事（青）。

- 面白は4つ。`Paternal_t` / `Paternal_jik` の1つ目 / `Paternal_ht` / `Paternal_jik` の2つ目 の順。
- 見事は `Paternal_mig` を2文字ずつに割ったもの。**種牡馬は4つ、繁殖牝馬は3つ**
  （全2,979頭で例外なし）。**固定4マスにせず、数に応じて伸縮させること。**
- 繁殖牝馬は血統表側に見事のコードを持たないので、必ず `Paternal_*` から組む。

**大きさに注意。** カードは760px基準で作られ、画面幅に合わせて縮小される
（375pxの端末で0.42倍）。**カード内での基準を20pxに取ること。** 0.42倍で約8.5pxとなり、
馬名と同じ大きさになる。11pxで作ると実質4.6pxで読めない。26pxでは馬名より目立ちすぎる。
モックはこの20pxで作ってある。

### 3. 血統表を既定で畳む（`IS_EMBEDDED` のとき）

「▼ 血統表を見る」で開き、「▲ 血統表を隠す」で閉じる。カードごとに独立した状態を持つ。

結果一覧は仮想スクロールで、行の実測高さを積み上げて位置を出している
（`src/features/search/ui/ResultsPanel.tsx` の `offsets`）。**開閉で高さが変わるので、
再計測が走ることを確認すること。** 開いたあとスクロール位置がずれないこと。

### 4. 選択と選択解除（`IS_PICKER` のとき）

いまは「カードをタップで選択 → 枠が青 → 下部バーで確定」で、解除はもう一度タップである。
これを**ゲームと同じ形**に変える。

- 選択中はカードを暗くし、中央に「選択を解除する」ボタンを重ねる。この状態は
  選択しているあいだ維持する。
- ボタンを押すと選択が外れる。
- 別のカードをタップすると選択が移る（1頭だけ）。
- **ボタンは縮小の外に置くこと。** カード内（760px基準）に入れると0.42倍で
  押せなくなる。モックでの実寸は153×52pxで、指で押せる大きさを確保している。

下部バー（「この馬を入れる」）は今までどおり残す。

## 受け入れ基準

1. `npm run build` が成功する（`tsc --noEmit` を含むので型エラーが無いこと）。

2. `npm run verify:parity` が成功する。

3. **単体の見た目が変わっていないこと。** ここが最重要である。
   変更前後で、iframe に入れずに直接開いたカードを比べ、**同一であること**を示す。

   a. 変更前の状態（`git stash` などで戻した状態）で `npm run dev` を起動し、
      検索して結果カードのスクリーンショットを撮る。

   b. 変更後の同じ条件で撮る。

   c. 2枚が同じであることを確認する。非凡・天性・因子カウント表・1薄め2薄め表・
      配合理論マークがすべて**残っている**こと。

   d. `?embed=1` を付けて**直接**（iframe 外で）開いても、単体と同じ見た目であること。

4. **埋め込みのときに項目が絞られていること。** iframe に入れて確認する。
   簡単な確認用 HTML を作ってよい（`<iframe src="...?embed=1">` を置くだけのもの）。

   a. 非凡・天性・因子カウント表・1薄め2薄め表・配合理論マークが**出ていない**。

   b. レア・馬名（因子付き）・9項目・血統表は出ている。

   c. 面白・見事が右上に2行で出ている。種牡馬は見事4つ、繁殖牝馬は見事3つ。

   d. 血統表が畳まれていて、ボタンで開閉できる。開いてもスクロール位置が飛ばない。

5. **`?picker=1` で選択・解除ができること。** カードをタップすると暗くなって
   「選択を解除する」が出る。押すと外れる。別のカードをタップすると選択が移る。
   下部バーの「この馬を入れる」が従来どおり動く。

6. 375px 幅で横スクロールが出ないこと。面白・見事が読める大きさで出ていること。

3〜6 で確認した内容を、完了報告に具体的に書くこと（スクリーンショットが撮れるなら添える）。
